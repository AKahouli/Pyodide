# Advisor Remediation Apply Workflow: Implementation Plan

## Goal

Make advisor "Preview changes" and "Apply changes" produce targeted, reviewable, deterministic playbook updates while reusing the existing frontend graph mutation logic in `handleApplyIntentSuggestion`.

Current issue: advisor findings are flattened into a generic natural-language intent, sent through the generic `/intent` pipeline, then applied as one coarse suggestion. This makes remediation naive, non-deterministic, and hard to preview accurately.

## Current Flow

Relevant frontend files:

- `YellowStorm/front/src/modules/playbook/components/ExecutionStepDetail.tsx` - builds advisor intent from selected findings.
- `YellowStorm/front/src/modules/playbook/components/AdvisorChangeReviewDialog.tsx` - lets users review, select, and edit remediation items.
- `YellowStorm/front/src/modules/playbook/components/PlaybookCanvasPage.tsx` - runs intent analysis and applies returned suggestions.

Relevant backend files:

- `YellowStorm/back/src/modules/playbook-flow/controllers/playbook-flow-execution-advisor.controller.ts` - exposes advisor evaluation and remediation endpoints.
- `YellowStorm/back/src/modules/playbook-flow/services/advisor/playbook-flow-execution-advisor.service.ts` - maps advisor results to remediation items.
- `YellowStorm/back/src/modules/playbook-flow/controllers/playbook-flow.controller.ts` - exposes the generic `/intent` endpoint.
- `YellowStorm/back/src/modules/playbook-flow/services/playbook-flow-intent.service.ts` - generates `PlaybookIntentSuggestion` objects from natural-language intent.

Current apply path:

```text
Selected advisor findings
        ↓
buildAdvisorIntent()
        ↓
POST /playbooks/:id/intent
        ↓
Generic intent service returns PlaybookIntentSuggestion
        ↓
handleApplyIntentSuggestion(topSuggestion)
        ↓
saveCurrentPlaybook()
```

## Phase 1: Constrain Current Flow

### Objective

Improve reliability quickly while keeping the existing `/intent` path.

### Scope

- Keep `handleApplyIntentSuggestion` unchanged.
- Keep the existing advisor remediation dialog.
- Improve the intent generated by `buildAdvisorIntent`.
- Add frontend validation before applying advisor suggestions.

### Changes

1. Strengthen `buildAdvisorIntent` for `optimize-step`.

Include:

- Current task title.
- Current task description.
- Selected advisor findings.
- Strict instruction to update only the selected task.
- Strict instruction to preserve all nodes, edges, ports, and data bindings unless required.
- Explicit instruction to return an `update_node` suggestion.
- Explicit instruction not to create, delete, reorder, or reconnect nodes.

2. Add frontend guard in `handleApplyAdvisorIntent`.

For `optimize-step`, reject suggestions unless:

```ts
suggestion.kind === 'single_change'
suggestion.operationType === 'update_node'
suggestion.targetTaskId === selectedTaskId
```

3. Improve user feedback.

If the returned suggestion tries to modify the graph outside the selected step, show an error such as:

```text
Advisor remediation returned changes outside the selected step. Please retry or edit the findings.
```

### Expected Result

- Fewer accidental graph changes.
- Advisor remediation mostly updates the target step description only.
- Existing undo, highlighting, graph state updates, and save behavior remain unchanged.

### Limitations

- Preview still shows findings, not exact before/after field diffs.
- Backend still interprets free-text instructions.
- The generic intent model may still produce incomplete or overbroad changes.

## Phase 2: Dedicated Advisor Remediation Preview/Apply

### Objective

Create a proper advisor-specific remediation pipeline that returns a structured `PlaybookIntentSuggestion`, then reuse the existing frontend apply engine.

### Scope

- Add a dedicated backend endpoint for advisor remediation preview.
- Keep frontend graph mutation centralized in `handleApplyIntentSuggestion`.
- Convert selected advisor findings into a structured suggestion before apply.
- Show exact changes before applying.

### Proposed Flow

```text
Selected advisor findings
+ target task
+ current playbook definition
        ↓
POST /playbooks/:id/advisor-remediations/preview
        ↓
Backend returns PlaybookIntentSuggestion
        ↓
Frontend previews exact changes
        ↓
User clicks Apply
        ↓
handleApplyIntentSuggestion(suggestion)
        ↓
saveCurrentPlaybook()
```

### Backend Endpoint

```http
POST /playbooks/:id/advisor-remediations/preview
```

Request:

```ts
{
  executionId: string;
  mode: 'optimize-step' | 'update-current' | 'generate-new';
  targetTaskId?: string;
  items: Array<{
    id: string;
    category: RemediationCategory;
    description: string;
  }>;
}
```

Response:

```ts
{
  suggestion: PlaybookIntentSuggestion;
  expectedDefinitionRevision: number;
}
```

### Backend Responsibilities

1. Load the current playbook.
2. Load the target task for `optimize-step`.
3. Pass structured remediation data to the LLM.
4. Require the LLM to return a valid `PlaybookIntentSuggestion`.
5. Validate the suggestion before returning it.

For `optimize-step`, enforce:

```ts
suggestion.kind === 'single_change'
suggestion.operationType === 'update_node'
suggestion.targetTaskId === targetTaskId
```

Allow ports or connections only if explicitly required and validated.

### Frontend Responsibilities

1. Replace generic advisor intent submission with the new preview endpoint.
2. Store the returned `PlaybookIntentSuggestion`.
3. Render a real before/after preview for:
   - Task title.
   - Task description.
   - Input ports.
   - Output ports.
   - Edges and data bindings, if changed.
4. On apply, call:

```ts
handleApplyIntentSuggestion(suggestion, {
  expectedDefinitionRevision,
});
```

### Expected Result

- Advisor preview becomes a real diff preview.
- Apply remains deterministic and idempotent.
- Existing undo, highlights, graph state updates, and save logic are reused.
- Advisor remediation becomes scoped, validated, and safer.

## Recommended Order

1. Implement Phase 1 first as a safety improvement.
2. Implement Phase 2 as the durable fix.
3. Once Phase 2 is stable, remove or deprecate advisor usage of the generic `/intent` path.

## Success Criteria

- Applying advisor remediation to one step does not modify unrelated steps.
- Preview shows the exact generated task changes before apply.
- Re-applying the same suggestion remains idempotent.
- Existing `handleApplyIntentSuggestion` remains the single frontend mutation path.
- Backend rejects advisor suggestions that violate the selected remediation scope.
