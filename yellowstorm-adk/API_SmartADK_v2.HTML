Application Bootstrap – main.py

Initialises logging, middleware, lifespan hooks and binds the Smart ADK routers to the FastAPI app.

lifespan(app: FastAPI)

Async lifespan context manager Initialises observability per deployment mode

Executed when the FastAPI app starts and stops. When Application Insights logging is enabled it configures structured logging, correlation identifiers, and Azure Monitor exporters; otherwise it boots the Elastic/console logging pipeline using environment toggles.

Responsibilities
  • Announces router availability on start and shutdown.
  • Branches between Application Insights and Elastic/console logging stacks.
  • Applies correlation ID filters when Application Insights logging is active.
  • Builds JSON/colour logging based on LOG_JSON_FORMAT and COLOR_LOGS environment variables.
Parameters
app: FastAPI application instance entering the lifespan.
Yield
Suspends after setup so FastAPI can serve requests, then resumes for teardown logging.

validation_exception_handler(request, exc)

FastAPI exception handler Returns RFC 7807 style validation responses

Catches RequestValidationError thrown by FastAPI/Pydantic, logs the issue with correlation metadata, and replies with HTTP 422 containing the aggregated validation errors.

Parameters
  • request: The incoming Starlette request used for contextual logging.
  • exc: The validation exception encapsulating field errors.
Returns
JSONResponse with {"detail": exc.errors()} and status 422.
Notes
Ensures even streaming endpoints surface structured validation issues to API clients.

Routers & Streaming Endpoints – routers/chatbot.py

Defines SSE streaming endpoints for classic RAG chat and multi-agent orchestration, guarded by bearer-token authentication.

_event_stream(q, bg_task)

Async generator Serialises queue events to SSE frames

Continuously awaits dictionary payloads on an asyncio.Queue, JSON serialises them, and yields Server-Sent Event formatted strings (data: ...\n\n). If a None sentinel is received or the client disconnects, it gracefully stops and cancels the background producer task.

Parameters
  • q: Queue populated by the orchestrator services.
  • bg_task: Background task responsible for streaming production, cancelled when the consumer leaves.
Raises
Propagates asyncio.CancelledError after logging so upstream StreamingResponse terminates cleanly.

chat_with_adk_endpoint(user_request, current_user)

POST /chatbots/chatWithADK StreamingResponse (text/event-stream)

Handles authenticated chat requests against the traditional Smart RAG engine. After verifying the JWT-derived user, it instantiates ChatRAGService, spawns a background task to process the request, and streams the orchestrated events to the client.

Parameters
  • user_request: Validated ChatWithADKRequest payload.
  • current_user: Active User injected via dependency (get_current_active_user).
Returns
Server-Sent Events stream summarising manager messages, tool calls, and final completion markers.
Error handling
Logs unexpected exceptions, aborts the background task, and surfaces a 500 JSON error response.

run_agent_team_endpoint(user_request, current_user)

POST /agentic/run_agent_team Streams multi-agent team execution

Bootstraps the multi-agent orchestration flow for complex tasks. It instantiates AgentTeamService, launches asynchronous processing of the agent workflow (auto-suggestion or manual selection), and relays streaming updates to the caller.

Parameters
  • user_request: Validated RunAgentTeamRequest with manager prompt, available agents, search options, and agent mode.
  • current_user: Authenticated principal ensuring task execution context.
Output
Emits description chunks, tool invocations, HTML snippets, and completion markers through SSE.
Error handling
Returns HTTP 500 with error details if orchestration raises an exception.

Chatbot Request Schemas – schema/chatbot_schema.py

Pydantic models describing the request contracts accepted by the chat and agentic endpoints.

ChatWithADKRequest

Pydantic BaseModel Represents classic RAG chat payload

Captures user identity, session, prompt, and retrieval configuration for the chat endpoint.

Key fields
  • user_id, session_id: Correlate streaming output to the caller.
  • message: Natural language query to the knowledge base.
  • chatbot_name: Dict describing the preferred model provider.
  • brain_documents, brain_relations, brain_ids: Optional dynamic knowledge graph inputs.
  • search_web, enable_multilingual, languages: Orchestration toggles.

AgentSuggestion

Pydantic BaseModel Describes a candidate specialised agent

Used both for suggested agents and existing catalog entries, including prompt, tools, document bindings, and fallback chatbot configuration.

Highlights
  • Supports optional tool lists (calculator, search, search_web, in_memory).
  • Stores document graph metadata for ingestion into search toolkits.

RunAgentTeamRequest

Pydantic BaseModel Aggregates manager prompt, agents, and orchestration mode

Defines the control payload for the multi-agent endpoint, including manual agent rosters or placeholders for automatic suggestion.

Notable fields
  • manager_prompt: Baseline instructions for the manager agent.
  • available_agents, agents: Provide initial agent pools and manual selections.
  • agent_mode: Chooses between auto suggestion and manual execution.
  • search_web, vectorstore_name, brain_documents: Fine-tune retrieval behaviour.

Authentication Helpers – authentification/get_current_user.py

Validates bearer tokens, manages Redis-backed user sessions, and ensures only active accounts can access endpoints.

RedisConnectionManager

Singleton Async connection pool manager

Creates and caches a single redis.asyncio connection pool configured either with TLS (rediss://) or plaintext (redis://) based on environment flags.

Key methods
  • __new__: Ensures the class behaves as a singleton.
  • get_connection_pool(): Lazily initialises the pool with retry-on-timeout behaviour and logs destination details.
  • get_redis_connection(): Returns a Redis client bound to the shared pool.
  • close_pool(): Gracefully disconnects and resets the cached pool.

get_redis_connection()

Convenience coroutine returning a Redis client from the shared connection manager, easing dependency injection.

get_user(r, username)

Redis lookup Returns UserInDB or None

Fetches the cached user JSON by username, logs retrieval outcomes, and instantiates UserInDB; returns None when the user is absent.

get_current_user(token)

Depends on OAuth2PasswordBearer Decodes JWT and validates session

Decodes the bearer token using the configured secret and algorithm, verifies the sub claim, retrieves the Redis-stored user, and raises HTTP 401 on any error.

Logging
Keeps detailed audit logs of token decoding, Redis lookup, and authentication success or failure.

get_current_active_user(current_user)

Ensures that the authenticated user is not flagged as disabled before allowing API access; otherwise returns HTTP 400 “Inactive user”.

Configuration Management – config/settings.py

Centralised environment-driven configuration with extensive validation for runtime critical settings.

Settings

Pydantic BaseSettings Strong validation on critical secrets and URLs

Encapsulates application, Azure, Redis, authentication, LLM, and tracing configuration. Numerous field validators guard against missing or malformed values, ensuring deployments fail fast if required variables are absent or invalid.

Highlighted validators
  • Azure storage/account secrets must be non-empty strings.
  • DATABASE_URL must start with supported schemes (PostgreSQL, MySQL, SQLite, MSSQL, Oracle).
  • URL fields (API_URL, LITELLM_API_BASE_URL, EXCEL_MCP_URL, LANGFUSE_HOST) are parsed with urlparse to guarantee scheme and host.
  • Numeric constraints on REDIS_PORT, concurrency limits, and similar toggles.

get_settings()

LRU cached Selects .env file based on ENVIRONMENT

Determines the active environment (local, dev, prod), loads the appropriate .env file, and returns a cached Settings instance for reuse across the application.

Middleware Suite – middleware package

Cross-cutting concerns for CORS, logging, tracing, and correlation propagation.

add_middleware(app, app_settings)

Registers CORS for all origins, and depending on Application Insights mode either installs CorrelationIdMiddleware or configures Structlog and Datadog tracing middleware for local/Elastic logging scenarios.

CorrelationIdMiddleware

Starlette BaseHTTPMiddleware Propagates correlation-id & user headers

Reads custom headers (correlation-id, user), stores them in contextvars, attaches them to OpenTelemetry spans, and ensures downstream responses echo the correlation identifier.

get_correlation_id() & get_user()

Expose the current request's correlation ID and user from the context variables for logging filters and trace enrichment.

add_cors(app)

Applies permissive CORS policy (all origins, headers, and methods) suitable for controlled API consumers.

add_logging(app)

Wraps requests in a Structlog-powered access logger replicating Uvicorn format while enriching events with request IDs, durations, and network metadata.

logging_middleware(request, call_next)

Measures request duration, captures unhandled exceptions, sets X-Process-Time headers, and logs structured access records. When exceptions occur, the middleware logs with api.error logger before re-raising.

add_tracing(app)

Ensures Datadog's TraceMiddleware sits at the outermost position to capture full request spans when tracing is enabled.

Logging & Telemetry – logger package

Utilities for consistent structured logging and optional ElasticSearch export.

CorrelationIdFilter

Augments log records with correlation ID, user, and component metadata by tapping into the middleware context.

configure_logging()

Builds a logging configuration for Application Insights mode, attaches CorrelationIdFilter, and sets formatted output covering level, timestamp, module, line, correlation ID, and user.

get_logger(name, setup_logger=False)

Returns a named logger, optionally bootstrapping Structlog/Datadog pipeline when setup_logger is True.

rename_event_key

Structlog processor renaming the event field to message for Datadog compatibility.

drop_color_message_key

Removes redundant color_message entries emitted by Uvicorn when formatting JSON logs.

tracer_injection

Enriches Structlog events with Datadog trace and span identifiers so traces correlate with log entries.

setup_logging(json_logs=False, log_level='INFO', color_logs=True)

Configures Structlog processors, selects JSON versus console renderers, patches Uvicorn loggers, suppresses verbose libraries, and installs a global exception hook.

handle_exception(exc_type, exc_value, exc_traceback)

Global exception hook capturing uncaught exceptions (except KeyboardInterrupt) and routing them through the structured logger.

elastic_search_logging(record, log_source, es_connection, index_name)

Persists log entries to ElasticSearch, auto-creating an index with mapped fields if necessary.

Traditional RAG Engine – smart_rag/engines/traditional

Single-agent retrieval augmented generation with hierarchical prompt orchestration and Langfuse tracing.

SmartRAGOrchestrator

Coordinates prompt extraction, agent creation, tool wiring, and streaming response handling for the classic Smart RAG workflow.

Key workflow steps
  • Extracts specialised prompts (agent, operator, report writer, HTML, manager, suggestion) via PromptProcessor.
  • Constructs document and brain trees from request payloads for search tooling.
  • Creates delegation functions for search, operator, report writer, and HTML agents using DelegationTools.
  • Initialises a manager agent with delegation tools, runs it via SessionHelper, and streams SSE events through StreamingFormatter.
  • Emits Langfuse traces for orchestration spans and ensures resources are cleaned up.

chat_smart_rag(user_request, queue) orchestrates the entire lifecycle, pushing structured streaming events onto the queue and terminating with a final end_of_message chunk.

EventExtractor

Utility class encapsulating methods to inspect Google ADK event objects.

Important methods
  • extract_function_call_info, extract_function_response_info, extract_text_content: Retrieve human-readable descriptions of streaming parts.
  • is_final_response, has_function_call, has_function_response: Boolean helpers for event routing.
  • extract_function_name, extract_function_args: Parse function call metadata from parts.
  • extract_error_info: Detects tool response errors.
  • extract_comprehensive_event_info: Aggregates multiple inspectors into a single dictionary.

Agent Core Utilities – smart_rag/agents/core

Helper classes for manipulating agent metadata, documents, and execution pipelines.

DocumentHelpers

Static utilities to merge brain documents/relations, deduplicate entries, and prepare document tree information for prompts.

Selected methods
  • _build_trees(user_request): Builds document and brain trees from raw payloads.
  • _store_original_brain_data: Preserves agent-specific brain data before merging for prompt optimisation.
  • _get_base_brain_documents, _get_base_brain_relations, _get_base_brain_ids: Resolve fallback context from team configuration or user request.
  • _combine_brain_documents, _combine_brain_relations, _combine_brain_ids, _merge_brain_relations: Merge agent-specific, team-level, and request-level knowledge configurations.
  • _merge_documents_without_duplicates, _extract_document_id: Prevent duplicate document entries when agents extend context.
  • _populate_brain_data, _get_agent_original_brain_documents, _get_agent_original_brain_relations: Enrich agent dictionaries with combined knowledge while retaining originals.
  • get_document_tree_info_without_ids, _remove_ids_from_tree, _remove_ids_from_brain_tree: Produce anonymised hierarchical descriptions suitable for manager prompts.
  • _get_consolidated_document_tree_info_for_manager: Summarises shared and agent-specific document availability.

AgentHelper

Normalises agent names, augments prompts with tool information, and prepares agent dictionaries for execution.

Key capabilities
  • sanitize_function_name: Produces safe function identifiers from arbitrary agent names.
  • normalize_agent_name: Standardises names for repository lookups.
  • get_document_tree_info: Formats document and brain trees for prompt inclusion.
  • pre_agent_run_config: Inserts default report writer/HTML agents, applies fallback chatbot names, and enriches descriptions with available tools.
  • _prepare_agent_data: Clones agent dicts, populates brain data using DocumentHelpers, and prunes unusable search tools.
  • _remove_search_if_empty: Removes the search tool when no documents or relations are available and annotates prompts accordingly.
  • _create_enhanced_manager_prompt: Builds manager instructions listing delegates and usage guidance.

AgentRepository

In-memory collection managing agent definitions, normalised lookups, and capability checks.

Methods
  • add_agent, set_agents: Insert or replace agent lists.
  • get_agent_by_name, get_agent_id_by_name: Resolve agent metadata and IDs case-insensitively.
  • get_all_agents: Returns the current roster.
  • has_search_agents: Flags whether any agent exposes search tools, used for prompt shaping.

AgentRunner

Executes Google ADK agents, streams intermediate events, and records Langfuse traces.

Primary methods
  • run_agent_tool: Handles session initialisation, agent type detection (standard/report/html), and streaming of task descriptions, chunks, sources, and final results.
  • _run_standard_agent: Iterates over streaming events, emits search and delegate notifications, records function calls/responses, and returns the final result along with MCP usage and execution summary.
  • _run_html_agent: Tailored streaming for HTML agents, chunking large payloads into 250-character segments.
  • _handle_function_call, _handle_final_response: Format and queue function call events and sources for downstream clients.

Agent Factories – smart_rag/agents/factories

Create, configure, and delegate specialised agents with toolkits, prompts, and observability hooks.

AgentFactory

Central factory for constructing Google ADK agents with optional calculators, search toolkits, MCP integrations, and HTML capabilities.

Signature methods
  • create_agent(...): Builds a generic agent with optional calculator, document search, and MCP toolset; automatically chooses between tool-capable and plain LLMs.
  • create_report_writer_agent(prompt, chatbot_name): Produces a report writer without tools.
  • create_html_agent(prompt, chatbot_name, tools, name): Creates an HTML/visualisation agent optionally configured with additional tools.
  • create_operator_agent(prompt, excel_mcp_headers, chatbot_name): Includes calculator and Excel MCP toolset when available.
  • create_search_agent(...): Assembles search-capable agents, generates document tree info, optionally adds perform_standard_search, and returns both the agent and SearchToolkit.
  • create_manager_agent(prompt, chatbot_name, tools): Builds the manager agent with delegation tools and additional context callback.
  • create_tools_for_agent(...): Convenience helper forwarding to ToolFactory for simple cases.

AgentDelegationFactory

Generates asynchronous delegate functions that the manager agent can call to execute specialised agents while maintaining Langfuse trace hierarchies.

Important methods
  • make_delegate_function(agent_name, q, search_web, parent_span): Returns an async delegate that records input/output spans, creates the agent on demand, and streams results.
  • _create_agent_with_error_handling(...): Validates agent availability, enhances prompts with tool descriptions, and instantiates the agent/toolkit pair.
  • _execute_agent_with_error_handling(...): Runs the agent via AgentRunner, records execution summaries, updates spans, and streams queue events.

create_agent_for_delegation(...)

Dispatcher choosing between create_search_agent_with_tools and create_standard_agent_with_tools depending on agent configuration.

create_regular_agent(...)

Builds non-HTML agents, optionally enabling search capabilities and web search depth based on tools.

prepare_agent_data(helper, config, agent_config, tools, base_enhanced_prompt, chatbot_name)

Constructs document/brain trees, enriches prompts, resolves brain IDs, vectorstore names, and normalises chatbot names before delegation.

get_enhanced_prompt(...)

Combines base prompts with document tree information when search tools are present.

create_search_agent_with_tools(...)

Initialises a search-enabled agent via AgentFactory.create_search_agent, stores toolkit references for source handling, and appends calculator tools when requested.

create_standard_agent_with_tools(...)

Constructs non-search agents, optionally layering calculator or web search utilities based on tool list.

ManagerAgentFactory

Produces the manager agent, injecting contextual callbacks and consolidated document overview when search agents exist.

Key operations
  • create_manager_agent(manager_prompt, tools, delegation_factory): Configures before/after callbacks to track search agent availability and maintain task order state.
  • _create_manager_instruction: Cleans the manager prompt, adds web search context, and appends document tree summaries.
  • _get_document_tree_info: Delegates to AgentHelper for formatted tree information.

ToolFactory

Constructs search tool wrappers, MCP toolsets, and determines when to enable web or in-memory extraction.

Highlights
  • create_search_tools: Generates SearchToolkit functions for document search, brain search, web search, and in-memory extraction depending on available schemas.
  • create_tools_for_agent: Adds calculator/search/web search tools based on flags.
  • create_mcp_toolset: Builds MCP toolsets from connection headers via MCPHelper.

create_enhanced_prompt(agent_config, tool_provider, agent_repository)

Combines base prompts with tool descriptions, citation requirements, and report sourcing rules when search agents are present.

process_execution_summary(execution_summary, delegation_span)

Iterates over execution flow entries, routing them to process_execution_step and attaching detailed Langfuse events.

process_execution_step(step, delegation_span)

Dispatches step handling based on type (function execution, text generation, error, etc.).

add_function_execution_event(step, delegation_span)

Emits Langfuse events for tool calls, ensuring input arguments and outputs are captured.

update_span_with_execution_result(delegation_span, result, execution_summary, agent_name)

Marks spans as success or failure based on execution statistics, including error counts when present.

determine_execution_success(execution_summary)

Returns True when no errors are recorded in the execution summary.

get_error_count(execution_summary)

Extracts aggregated error counts, defaulting to zero when absent.

Agent Suggestion Engine – smart_rag/agents/generators

Analyses user prompts to propose relevant specialised agents and parse model responses.

AgentSuggestionGenerator

Produces suggestions by prompting an LLM, supports structured output when available, and maps suggestion IDs back to pre-existing agents.

Core methods
  • generate_suggestions(suggestions_prompt, user_prompt, available_agents, config, ...): Formats prompts with available agents, runs the suggestion agent, and returns parsed suggestions with an ID mapping.
  • _create_suggestion_agent: Builds the generator agent, configuring output_schema if the chosen model supports structured output, otherwise injecting JSON instructions into the prompt.
  • _run_suggestion_agent: Manages the ADK session, streams events, and parses the first non-empty suggestion payload.

model_supports_structured_output(model_name)

Heuristic determining whether a model can natively emit structured JSON (excludes known OSS GPT variants).

parse_suggestions_response(response)

Attempts to parse JSON from model responses; falls back to extract_json_from_text when plain-text output is returned.

extract_json_from_text(text)

Uses regex to locate JSON fragments inside free-form responses and parses them, returning empty structures when parsing fails.

Delegation & Tool Management – smart_rag/agents/tools

Handles creation of delegate functions exposed to the manager and extraction of agent mentions from prompts.

DelegationTools

Builds predefined delegate coroutines for search, operator, report writer, and HTML agents. Each delegate manages Langfuse spans, streams queue updates, and handles MCP file uploads or errors.

Delegate responsibilities
  • Search delegate: Configures SearchToolkit, records function execution flow, and streams source metadata.
  • Operator delegate: Executes calculator/MCP tasks, uploads files to the data lake, and streams file metadata.
  • Report writer delegate: Produces synthesised reports and marks spans according to success state.
  • HTML delegate: Streams HTML chunks and updates execution spans.

AgentToolsManager

Parses @agent mentions from user prompts, generates corresponding delegate functions via AgentDelegationFactory, and provides fallbacks when no mentions are found.

Key methods
  • extract_agent_tools_from_mentions(user_prompt, q, search_web): Detects mentions, sanitises names, and builds delegate functions.
  • create_tools_from_all_agents(q, search_web): Creates delegates for every repository agent when no mentions are provided.
  • get_agent_tools(user_prompt, q, search_web): Preferred entry point combining mention extraction with all-agent fallback and error reporting.

LLM Factory – smart_rag/infrastructure/factories

Creates LiteLLM-backed adapters for Azure OpenAI, OpenRouter, and Ollama models while injecting user context.

LLMFactory

Provides two static constructors:

  • create_parallel_tool_calls_llm(model_name): Builds a streaming LLM with parallel tool calls disabled (or Ollama equivalent) suitable for tool-enabled agents.
  • create_no_tool_calls_llm(model_name): Returns a streaming LLM without tool invocation support.

Both methods detect dictionary-based chatbot descriptors, extract provider identifiers, set environment variables for Ollama, and log model creation success.

Prompt & Callback Processing – smart_rag/infrastructure/processing

Cleans prompts, builds contextual history, and injects additional context/images before and after tool execution.

PromptProcessor

Handles prompt extraction and normalisation.

Key methods
  • extract_chatbot_name_and_clean_prompt: Detects chatbot tags in prompts and strips them from instructions.
  • extract_prompts: Splits composite prompt descriptions into agent-specific segments.
  • get_web_search_prompt(index): Retrieves canned web search guidance from environment configuration.
  • extract_task_description: Pulls task descriptions from tagged text.
  • clean_prompt_text, validate_prompt_structure, merge_prompts_with_context, process_manager_prompt, process_agent_prompt: Normalise whitespace, ensure required sections exist, and merge context snippets.

ContextBuilder

Builds structured context strings from previous session events, differentiating manager-specific and agent-specific views by including recent responses.

add_additional_context(tool, args, tool_context)

Before-tool callback that appends structured context to delegate calls, enforces presence of expected_output and task_description, increments task order counters for search agents, and strips source tags when handing context to search delegates.

get_structured_context(events, search_agent=False)

Formats prior session events into XML-like blocks for additional context, removing source tags for search agents to avoid duplication.

catch_images_after_tool(tool, args, tool_context, tool_response)

Post-tool callback for search functions that buffers images, annotates text sources with ordering, and returns cleaned source lists to the agent.

inject_images_before_model(callback_context, llm_request)

Pre-model callback that injects buffered images (with filenames) into the LLM request content and clears the buffer.

External Integrations – smart_rag/infrastructure/external

Bridges Smart ADK with external MCP servers and emits system-level queue messages.

MCPHelper

Static helper for interacting with the Excel MCP server.

  • create_excel_mcp_headers: Encodes brain documents and session metadata into HTTP headers.
  • upload_files_to_datalake: Opens SSE client connections, initialises MCP sessions, invokes the upload_files tool, and parses results.
  • validate_mcp_headers: Ensures required headers are present.
  • create_mcp_connection_params, create_mcp_toolset: Build Google ADK MCP toolset instances from header metadata.

create_common_helpers(file_path="./tmp")

Factory exposed for convenience (implemented in smart_rag/tools/infrastructure/common_helpers.py) that instantiates CommonHelpers for shared file operations.

MessageHelper

Provides internal methods _send_suggestions and _send_error_message to push structured system updates into streaming queues (using constants such as SYSTEM_AGENT_NAME and SUGGESTIONS_CONTENT_TYPE).

Session Management – smart_rag/infrastructure/session

Provides resilient database-backed sessions for Google ADK agents.

PatchedDatabaseSessionService

Extends the default ADK DatabaseSessionService to enable connection pooling with health checks, recycling, and overflow limits.

SessionHelper

Lifecycle manager for ADK sessions per user.

  • init_session(agent, session_id=None): Ensures sessions exist (creating when needed), initialises Runner, and returns the session ID.
  • set_session(): Reuses existing sessions when available, otherwise creates new ones.
  • add_exit_stack: Registers async exit stacks for cleanup.
  • cleanup(): Closes exit stacks, disposes database engines, and resets internal state.

Monitoring & Tracing – smart_rag/infrastructure/monitoring

Integrates Langfuse tracing and exposes helper utilities to capture agent execution flow.

TraceRecorder

Aggregates text chunks, function calls, responses, and errors for each agent, producing structured execution summaries consumed by Langfuse spans.

Notable methods
  • record_chunk, record_function_call, record_function_response, record_error, record_final_result: Append corresponding events to the history.
  • get_execution_summary: Merges history into chronological execution steps with statistics (text length, function call count, errors, final result).
  • _get_timestamp: Supplies timestamps for recorded events.

The module also initialises a reusable langfuse_client and OTEL exporter headers derived from settings.

Shared Tool Utilities – smart_rag/tools/infrastructure

Provides reusable helpers for file downloads, vectorstore interactions, and tool documentation.

CommonHelpers

Asynchronous utility class for document retrieval and vectorstore calls.

Key methods
  • async_download_from_azure_datalake: Streams files from Azure Data Lake to local storage, supporting SSL and asynchronous writes.
  • create_search_payload: Generates standardised payloads for similarity search endpoints.
  • create_text_object, create_image_object: Normalise search results into consistent dictionaries.
  • process_image_downloads, process_downloaded_images, wrap_images: Download, read, and base64-encode images for tool injection.
  • filter_ids: Filters attribute mappings based on user-provided filters (with special handling for id lookups).
  • post_vectorstore: Executes local similarity search requests using the integrated vectorstore functionality.
  • validate_metadata, extract_filename_from_path, ensure_directory_exists: Utility helpers for metadata validation and filesystem hygiene.

ToolDescriptionProvider

Supplies human-readable tool descriptions and citation requirements to enrich agent prompts. Methods include:

  • get_tools_description: Formats markdown sections describing each available tool.
  • get_source_citation_requirements: Returns detailed instructions for citing document, in-memory, and web sources.
  • get_source_reference_requirements_for_reports: Tailors citation guidance for report writer outputs.

Search Tools & Toolkit – smart_rag/tools/search

Implements document, brain, in-memory, and web search utilities along with helper schemas.

SearchToolADK

Extends Google ADK's FunctionTool to use pre-built JSON schemas, ensuring consistent function declarations for search actions.

get_transformed_ids_by_names(attribute_mapping, names)

Returns transformed brain IDs associated with name attributes, supporting both single values and lists.

create_search_schema(name, description, properties, required)

Generates JSON schema dictionaries describing search functions.

validate_search_parameters(params, schema)

Ensures required parameters are present before executing search functions.

get_attribute_mapping_info(attribute_mapping)

Summarises attribute mapping statistics for diagnostics (total attributes, values, IDs).

SearchResultProcessor

Static helper with methods deduplicate_by_id, format_search_response, and extract_metadata_fields to post-process search results.

SearchToolkit

Comprehensive toolkit orchestrating document, brain, in-memory, and web search across Smart ADK knowledge sources.

Key methods
  • perform_standard_search(query): Executes combined text/image searches and returns sources plus filenames.
  • perform_document_search(query, **filters): Applies attribute filters before performing standard search.
  • preform_all_brain_search(query, brain_name, document_filter): Focuses search on specific brains or documents.
  • perform_in_memory_extraction(file_name): Retrieves full content of in-memory documents, handling download/read errors.
  • perform_web_search(query): Delegates to WebSearchTool when enabled.
  • set_in_memory_documents(doc_tree, in_memory_attribute_mapping): Registers in-memory files for later extraction.
  • generate_search_function, generate_generic_function, generate_function: Dynamically create callable wrappers with validated signatures and OpenAI-compatible schemas.
  • Private helpers _search_text_documents, _search_image_documents, _empty_search_result, get_search_stats support retrieval and analytics.

WebSearchTool

Async LinkUp API client capable of standard or deep searches, returning formatted answers and sources.

  • perform_web_search, web_search: Execute searches with depth selection.
  • _format_search_response: Formats answers with bullet-point sources.
  • search_with_filters: Allows custom output types.
  • get_search_capabilities, validate_api_key: Provide introspection and validation.

web_search(query, search_web="standard")

Legacy convenience coroutine that instantiates WebSearchTool and delegates to web_search.

create_web_search_tool(api_key=None)

Factory returning a WebSearchTool with optional custom API key.

Multi-agent Workflow Orchestration – smart_rag/engines/multi_agent

Coordinates suggestion, selection, and execution of multiple specialised agents with real-time streaming and tracing.

run_agent_team_logic(user_request, q)

Entry point for multi-agent requests: creates a Langfuse trace, initialises dependencies, builds configuration, constructs the auto-agent team, and invokes execute_workflow. Marks traces as success or failure and flushes Langfuse buffers.

execute_workflow(team, user_request, q, main_trace)

Selects the appropriate workflow based on agent_mode: auto triggers handle_no_agents_workflow, manual triggers handle_agents_provided_workflow.

AutoAgentGenerationTeam

Central orchestrator maintaining agent repositories, generating suggestions, creating manager agents, and processing streaming events.

Key methods
  • __init__: Wires prompt processors, LLM factory, agent factory, runner, streaming formatter, suggestion generator, and supporting helpers.
  • get_agent_id_by_name, has_search_agents, get_document_tree_info: Convenience accessors for agent metadata.
  • get_agent_suggestions: Invokes suggestion generator, enriches suggestions with brain data, updates repository, and returns aggregated agents.
  • make_delegate_function: Forwards to AgentDelegationFactory.
  • run_agent_team(user_prompt, manager_prompt, session_id, q, parent_trace): Creates manager agent tools, initialises sessions, processes streaming events, and flushes Langfuse traces.

StreamingEventProcessor

Consumes streaming events from the manager agent, emits SSE payloads, tracks delegations, and updates Langfuse spans with generated text.

Methods
  • process_streaming_events(session_helper, session_id, user_prompt, manager_agent, agent_runner, q, span): Core loop iterating through ADK events and delegating to _handle_event_parts.
  • _handle_event_parts(event, manager_agent, message_id, q, span, delegation_count, accumulated_text): Processes text, function calls/responses, final responses, and updates counters.
  • _handle_text_event, _handle_final_response: Format SSE payloads for manager chunks and completions.

initialize_dependencies()

Instantiates PromptProcessor, LLMFactory, AgentFactory, StreamingFormatter, EventExtractor, and AgentRunner used by the team.

create_team_config(user_request)

Builds AgentTeamConfig by constructing document/brain trees from the request and capturing vectorstore settings.

create_team(config, dependencies)

Creates an AutoAgentGenerationTeam using prepared dependencies and configuration.

handle_no_agents_workflow(team, user_request, q, main_trace)

Generates agent suggestions, streams them to the client, and if successful, calls _run_team_with_suggestions; otherwise emits error messages.

_run_team_with_suggestions(team, user_request, suggestions, q, main_trace)

Enhances manager prompts with suggested agents, runs the agent team, and records Langfuse events for prompt enrichment and execution outcomes.

handle_agents_provided_workflow(team, user_request, q, main_trace)

Adds manually provided agents to the repository (preparing their brain data), enhances prompts, and executes the team via _run_provided_agent_team.

_run_provided_agent_team(team, user_request, manager_prompt, session_id, q)

Builds enhanced manager prompts listing provided agents, constructs the manager user prompt, and runs the team with streaming updates.
