Router : chatbot_router

Module
src.routers.chatbot
Préfixe
/chatbots
Tags OpenAPI
["chatbots"]
Authentification
JWT Bearer via get_current_active_user

Ce router regroupe les interactions conversationnelles classiques avec l'ADK. Il s'appuie sur le service ChatRAGService pour orchestrer les workflows RAG traditionnels et fournit une réponse continue via Server-Sent Events (SSE).[1]

Utilitaire : _event_stream

Générateur asynchrone qui transforme les éléments extraits d'une file asyncio.Queue en événements SSE. Chaque bloc JSON est sérialisé puis envoyé avec l'en-tête data:, ce qui permet un streaming compatible navigateur. Le générateur surveille également les annulations afin d'arrêter la tâche d'arrière-plan lorsque le client se déconnecte.[1]

Flux de vie
  1. Lecture bloquante sur la queue jusqu'à réception d'un dictionnaire ou de None.
  2. Conversion en chaîne SSE : data: {<payload JSON>}\n\n.
  3. Détection d'annulation client : journalisation puis arrêt de la tâche de fond.

Endpoint : POST /chatbots/chatWithADK

Fonction Python
chat_with_adk_endpoint
Réponse
StreamingResponse (text/event-stream)
Service métier
ChatRAGService.process_chat_request

Déclenche un échange avec le moteur RAG traditionnel. Après validation de l'utilisateur actif, la requête est confiée à ChatRAGService qui délègue à SmartRAGOrchestrator. Les éléments de réponse sont insérés dans la file de streaming, puis diffusés au client via SSE.[1], [2]

Corps de requête : ChatWithADKRequest

Champ Type Obligatoire Défaut Description
user_id str Oui — Identifiant métier de l'utilisateur consommateur du service.
session_id str Oui — Session conversationnelle à enrichir.
max_tokens int Non 512 Limite de génération pour le modèle de langage.
instructions str | None Non None Guidelines additionnelles transmises au moteur.

top_k int Non 2 Nombre maximal de documents récupérés pour enrichir la réponse.
vectorstore_name str | None Non "vectorstorerec" Vector store principal pour la recherche de contexte.
brain_ids List[str] | None Non None Sources neuronales explicites à charger.
enable_multilingual bool Non false Active la génération multilingue.
brain_documents List | None Non None Documents à greffer dynamiquement à la base de connaissances.
brain_relations Dict | None Non None Relations graphe pour contextualiser les documents.

search_web bool | None Non false Autorise un fallback vers la recherche web.

Une erreur inattendue déclenche une réponse HTTP 500 avec un détail reprenant l'exception interceptée.[1]

Router : agentic_router

Module
src.routers.chatbot
Préfixe
/agentic
Tags OpenAPI
["agentic_rag"]
Authentification
JWT Bearer via get_current_active_user

Ce router expose la logique multi-agents permettant de piloter une équipe de spécialistes virtuels. Les flux de sortie utilisent le même mécanisme SSE que le router chatbot afin de présenter les avancées en temps réel.[1]

Endpoint : POST /agentic/run_agent_team

Fonction Python
run_agent_team_endpoint
Réponse
StreamingResponse (text/event-stream)
Service métier
AgentTeamService.process_team_request

Lance un workflow agentique orchestré par run_agent_team_logic via AgentTeamService. L'appelant peut fournir sa propre composition d'agents ou laisser le système sélectionner la meilleure équipe. Les résultats sont remontés par SSE au fur et à mesure de l'exécution.[1], [3]

Corps de requête : RunAgentTeamRequest

Champ Type Obligatoire Défaut Description
user_id str Oui — Identifiant de l'utilisateur pilote de la mission agentique.
session_id str Oui — Session à laquelle rattacher le workflow.
message str Oui — Objectif ou brief partagé avec les agents.
manager_prompt str Non "You are a manager agent..." Instruction initiale donnée à l'agent manager.
chatbot_name dict Oui — Paramétrage du collectif conversationnel.
agents List[AgentSuggestion] | None Non [] Agents imposés par le client. À vide, le manager sélectionne.
available_agents List[AgentSuggestion] | None Non [] Catalogue alternatif proposé au manager.
top_k int Non 10 Nombre d'éléments contextuels à récupérer.
vectorstore_name str Non "default" Vector store multi-agent prioritaire.
brain_ids List[str] | None Non None Brains explicites à aligner avec l'équipe.
brain_documents List | None Non None Documents complémentaires pour la mission.
brain_relations Dict | None Non None Relations graphe décrivant les liens entre ressources.
search_web bool | None Non false Active la recherche web si nécessaire.
agent_mode str Oui — Mode opératoire (ex. brainstorming, synthèse, exécution technique).

Structure imbriquée : AgentSuggestion

Les éléments de agents et available_agents utilisent ce modèle, qui décrit un agent individuel (identité, description, prompt, outils disponibles et configuration de vector store).[4]

Comme pour l'endpoint précédent, toute exception non gérée se traduit par une réponse HTTP 500 détaillant la cause côté serveur.[1]

Router agrégateur : router

Le module déclare également un router racine qui inclut chatbot_router et agentic_router. Ce composant est destiné à être monté dans l'application FastAPI principale pour exposer l'ensemble des routes documentées ci-dessus sous leurs préfixes respectifs.[1]

Authentification & Sécurité

Les deux endpoints utilisent la dépendance get_current_active_user. Celle-ci vérifie le jeton JWT via OAuth2PasswordBearer, récupère l'utilisateur correspondant dans Redis, puis confirme que le compte n'est pas désactivé avant de laisser passer la requête.[5]
