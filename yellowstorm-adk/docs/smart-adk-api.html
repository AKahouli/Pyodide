1. Aperçu général

Version: V1

BasePath par défaut: http://localhost:8001

L’API FastAPI Smart ADK API expose deux routes regroupées sous les préfixes /chatbots et /agentic. Chaque route retourne une réponse diffusée par flux SSE, permettant d’afficher en temps réel la production des agents cognitifs.[1]

2. Authentification & sécurité

Toutes les routes exigent un jeton Bearer valide. Le service d’authentification repose sur le flux OAuth2 Password : FastAPI fournit un schéma OAuth2PasswordBearer dont l’URL du jeton est {API_URL}token. Le jeton JWT doit être présenté dans l’en-tête Authorization: Bearer <token>.[2]

Lorsqu’une requête arrive :

  • le jeton est validé et décodé pour récupérer l’identifiant utilisateur,
  • les informations du compte sont chargées depuis Redis,
  • si l’utilisateur est inactif ou inconnu, une erreur 401 ou 400 est levée.

3. Format de réponse Server-Sent Events

Les deux endpoints retournent une réponse de type text/event-stream. Chaque événement SSE encapsule un objet JSON sérialisé via la clé data:.[1]

Structure générale d’un événement

Champ Type Description
agent_id string Identifiant interne de l’agent émetteur (si disponible, sinon "no_id").
agent_name string Nom de l’agent (« manager », « system », etc.).
agent_type string Type fonctionnel (manager, agent, html, suggestions, ...).
chunk string Contenu diffusé (texte, JSON ou indicateur end_of_message).
message_id string Identifiant du message courant dans la conversation.
message_type string streaming pour les flux en continu, no-streaming pour les messages système, ou error en cas d’incident.[3]
content_type string Nature du contenu : chunk, description, function_call, source, File, error, final_response, suggestions, etc.[3], [4]

Exemple de trame SSE reçue par le client : 

data: {"agent_name": "manager", "agent_type": "manager", "chunk": "Bonjour, que puis-je faire pour vous ?", "message_id": "...", "message_type": "streaming", "content_type": "chunk"}

4. Gestion des erreurs

  • 401 Unauthorized – jeton invalide ou utilisateur inexistant.[2]
  • 400 Bad Request – utilisateur authentifié mais inactif.[2]
  • 422 Unprocessable Entity – erreur de validation Pydantic (schéma JSON incorrect).
  • 500 Internal Server Error – exception inattendue durant le traitement asynchrone.[1]
Chatbots

5. POST /chatbots/chatWithADK

Lance un dialogue RAG classique avec l’ADK. Le service ChatRAGService orchestre les appels à l’engine traditionnel et renvoie les contributions du manager en flux continu.[1]

Body (JSON)

Paramètre Type Obligatoire Par défaut Description
user_id string Oui — Identifiant unique de l’utilisateur à des fins de traçabilité.
session_id string Oui — Identifiant de session Langfuse / conversation.
message string Oui — Prompt utilisateur initial.
chatbot_name object Oui — Description du fournisseur/modèle à utiliser (ex: {"provider": "gpt-4"}).
max_tokens integer Non 512 Budget de tokens pour la réponse.
instructions string Non null Prompt système additionnel pour personnaliser le comportement.
top_k integer Non 2 Nombre de documents à récupérer depuis la base vectorielle.
vectorstore_name string Non "vectorstorerec" Nom de la base vectorielle à interroger.
brain_ids array<string> Non null Identifiants de connaissances à charger.
brain_documents array Non null Documents supplémentaires passés à l’orchestrateur.
brain_relations object Non null Relations graphe (nodes/relationships) liées aux documents.
languages array<string> Non null Langues attendues pour la réponse.
enable_multilingual boolean Non false Active la rédaction multilingue si le modèle le permet.
search_web boolean Non false Autorise la recherche web externe lors du raisonnement.

Exemple de requête

POST /chatbots/chatWithADK
Authorization: Bearer <token>
Content-Type: application/json

{
  "user_id": "user-123",
  "session_id": "sess-456",
  "message": "Résume les tendances ESG 2023",
  "chatbot_name": { "provider": "gpt-4" },
  "brain_ids": ["knowledge-base-1"],
  "search_web": true
}

Flux de sortie typique

data: {"agent_name": "manager", "agent_type": "manager", "chunk": "Recherche interne : ESG 2023", "message_id": "...", "message_type": "streaming", "content_type": "chunk"}

data: {"agent_name": "manager", "agent_type": "manager", "chunk": "end_of_message", "message_id": "...", "message_type": "streaming", "content_type": "final_response"}
Agentic RAG

6. POST /agentic/run_agent_team

Lance une orchestration multi-agents. Selon le mode (auto ou manual), la plateforme peut suggérer des agents spécialisés ou exploiter une liste explicitement fournie.[1], [5]

Body (JSON)

Paramètre Type Obligatoire Par défaut Description
user_id string Oui — Identifiant utilisateur.
session_id string Oui — Identifiant de session global (Langfuse).
message string Oui — Demande utilisateur à traiter.
chatbot_name object Oui — Configuration du modèle à employer.
agent_mode string Oui — "auto" pour demander des suggestions, "manual" pour utiliser la liste fournie.
manager_prompt string Non "You are a manager agent..." Prompt système du manager (peut contenir des balises spéciales et instructions).
agents array<AgentSuggestion> Non [] Agents à pré-configurer quand agent_mode = "manual".
available_agents array<AgentSuggestion> Non [] Catalogue d’agents existants utilisables pour les suggestions.
top_k integer Non 10 Nombre maximum de résultats lors des recherches documentaires.
vectorstore_name string Non "default" Entrepôt vectoriel à consulter.
brain_ids array<string> Non null Identifiants de connaissances (même logique que ci-dessus).
brain_documents array Non null Documents à injecter dans le contexte des agents.
brain_relations object Non null Relations graphe (nœuds, arêtes) pour la navigation de connaissances.
search_web boolean Non false Permet aux agents de déléguer des recherches web.

Structure AgentSuggestion

Champ Type Par défaut Description
id string "no_id" Identifiant optionnel de l’agent.
name string — Nom utilisé par le manager pour invoquer l’agent.
description string — Rôle/metiers de l’agent.
prompt string — Instructions système propres à cet agent.
tools array<string> null Liste des outils accessibles (search, search_web, calculator, ...).
vectorstore_name string "vectorstorerec" Base vectorielle associée à l’agent.
brain_ids array<string> [] Knowledge bases accessibles.
brain_documents array [] Documents pré-chargés.
brain_relations object {"nodes": [], "relationships": []} Graphes de relations utilisables pendant la recherche.
chatbot_name object null Spécifie un modèle différent pour l’agent (sinon hérite de la requête).

Exemple de requête (agent_mode = "auto")

POST /agentic/run_agent_team
Authorization: Bearer <token>
Content-Type: application/json

{
  "user_id": "user-123",
  "session_id": "sess-456",
  "message": "Crée un plan marketing pour notre nouveau produit IA",
  "chatbot_name": { "provider": "gpt-4" },
  "agent_mode": "auto",
  "available_agents": [],
  "brain_ids": ["marketing-base"],
  "search_web": true
}

Flux de sortie typique

data: {"agent_name": "system", "agent_type": "suggestions", "chunk": "[{...}]", "message_id": "sess-456", "message_type": "no-streaming", "content_type": "suggestions"}

data: {"agent_name": "manager", "agent_type": "manager", "chunk": "@analyst commence la recherche documentaire", "message_id": "...", "message_type": "streaming", "content_type": "chunk"}

data: {"agent_name": "manager", "agent_type": "manager", "chunk": "end_of_message", "message_id": "...", "message_type": "streaming", "content_type": "final_response"}

En mode manuel, la trame de suggestions n’est pas envoyée. Les agents fournis sont préconfigurés avant exécution.[5]

7. Codes HTTP récurrents

200 OK

La requête est acceptée ; le flux SSE débute immédiatement.

400 Bad Request

Compte utilisateur inactif.

401 Unauthorized

Jeton manquant ou invalide.

422 Unprocessable Entity

Schéma JSON invalide (erreurs Pydantic).

500 Internal Server Error

Erreur serveur pendant le traitement asynchrone.
