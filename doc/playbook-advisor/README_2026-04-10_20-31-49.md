# Playbook Advisor

> **Slug:** `playbook-advisor` | **Status:** 🚧 draft | **Last Updated:** 2026-04-10 20:31:49 UTC

## Purpose
Document the shipped Playbook Advisor implementation that rebrands the previous judge/reflection UX and adds tool-aware advisor findings to step and execution summaries.

## Scope
Includes user-facing Playbook Advisor naming in the playbook frontend, tool-aware advisor prompt contracts, defensive backend advisor payload normalization, persisted advisor result fields, execution-summary tool usage findings, and localized advisor toasts/tooltips.

## Implemented
- User-facing playbook execution copy now uses `Playbook Advisor` / `Advisor` instead of `Judge LLM` / `Reflection` in the main tab, toolbar toggle, node badges/tooltips, and remediation actions.
- The backend still preserves existing `judge*` field names, routes, and prompt keys for compatibility.
- Step-level advisor results now normalize and persist these additional fields: `confidence`, `toolUsageScore`, `toolSelectionIssues`, `missingToolCalls`, `redundantToolCalls`, `toolOutputUseIssues`, `toolSequencingIssues`, `toolUsageStrengths`, `toolUsageRecommendation`, and `safeAutoFixType`.
- Execution-level advisor summaries now normalize and persist these additional fields: `confidence`, `toolUsageIssues`, `crossStepToolPatterns`, `rootCauseTaskIds`, and `highImpactRecommendations`.
- `PlaybookJudgeEnrichmentService` now normalizes advisor payloads defensively so malformed LLM JSON degrades to bounded defaults instead of leaking invalid data into persistence or the UI.
- The execution summary prompt now receives each completed step's `toolTrace` and `llmPromptTrace` alongside the existing judge result so the summary can reason about repeated tool misuse patterns.
- The Playbook Advisor detail view now renders tool-usage findings separately from the existing content-quality issue buckets and surfaces summary-level tool patterns when only the execution summary is available.
- Playbook prompt template titles and descriptions in the admin-facing registry now refer to Playbook Advisor wording while keeping existing keys unchanged.

## Validation
- Backend: `npm test -- modules/playbook/services/playbook-judge-enrichment.service.spec.ts --runInBand`
- Frontend: `npm test -- src/modules/playbook/components/ExecutionStepDetail.test.tsx src/modules/playbook/components/PlaybookToolbar.test.tsx`
- Backend build: `npm run build`
- Frontend build: `npm run build`

## Known Gaps
- `Advisor Autopilot` is not implemented yet. Execution remains asynchronous and advisory-only after step completion.
- Existing backend naming remains `judge*` by design in this phase to avoid route, schema, SSE, and stored-data migrations.
- Existing historical executions may have older advisor payloads without the new tool-aware fields until they are re-evaluated.
