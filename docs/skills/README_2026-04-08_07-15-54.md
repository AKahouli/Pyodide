# Skills

> Snapshot: 2026-04-08 07:15 UTC

This feature adds a structured skill catalog to YellowStorm agents, compatible with the AgentSkills-style workflow: skills are stored centrally, attached to agents or agent types, injected into prompts as a compact catalog, and lazily activated when needed.

## Scope

- Backend skill catalog CRUD and import
- Frontend skill management UI
- Skill inheritance on agent types and agents
- ADK runtime skill catalog injection and activation
- Playbook skill catalog injection and activation
- Separate legacy memory-based skills endpoint

## Backend Model

### Skill entity

The NestJS backend stores skills in MongoDB with the following fields:

- `name`
- `description`
- `license`
- `compatibility`
- `metadata`
- `allowedTools`
- `instructions`
- `files`
- `isActive`
- `createdBy`
- timestamps

Skill names are validated as lowercase hyphenated slugs.

### Associations

- `AgentType.skills` holds default skills for agents of that type.
- `Agent.skills` holds direct skills for a single agent.
- `Agent.disabledSkills` disables inherited type skills for that agent.
- Effective runtime skills are resolved as:
  - agent type skills
  - plus direct agent skills
  - minus disabled skills

## Backend APIs

### Admin skill management

- `GET /admin/skills`
- `GET /admin/skills/:id`
- `POST /admin/skills`
- `POST /admin/skills/import`
- `PATCH /admin/skills/:id`
- `DELETE /admin/skills/:id`

### Public selector endpoint

- `GET /skills/active`

Only active skills are returned by the selector path.

## Import Format

The import endpoint accepts:

- a raw `.md` file containing `SKILL.md`
- a `.zip` package containing `SKILL.md`

The importer parses YAML frontmatter and body instructions from `SKILL.md`.

Required frontmatter fields:

- `name`
- `description`

Supported optional fields:

- `license`
- `compatibility`
- `metadata`
- `allowed-tools`

Bundled files are stored with path metadata and classified as `reference` or `asset`.

## Frontend

The admin UI now includes a dedicated Skills page with:

- list/search/pagination
- create/edit dialog
- active/inactive toggle
- delete confirmation
- `.md` / `.zip` import flow

Agent and agent-type dialogs now load active skills for selection.

Supported UI behaviors:

- agent types can inherit skills
- agents can add direct skills
- agents can disable inherited skills

## ADK Runtime

### Shared skill runtime

`yellowstorm-adk/src/skills/runtime.py` provides:

- `inject_skill_catalog(prompt, skills)`
- `make_activate_skill_tool(skills)`

The catalog is injected as `<available_skills>` and the model is instructed to call `activate_skill` when a task matches a skill description.

### Conversation mode

`SingleAgentService` now passes skills into ADK agent construction, so single-agent conversation mode receives the skill catalog and lazy activation tool.

### Team mode

`base_factory.py` injects the same skill catalog for team agents.

## Playbook Runtime

Playbook execution also injects the skill catalog into task prompts.

- `graph_builder.py` injects skills into the system prompt.
- `step_executor.py` applies the same catalog injection for step execution.
- `playbook_tool_factory.py` adds an `activate_skill` tool when skills are present.

## Legacy Memory Endpoint

There is also a separate endpoint:

- `POST /config_agents_with_skills`

This path stores a free-form skills string in memory through `SkillsService` and is distinct from the structured MongoDB skill catalog.

## Limitations

- The structured skill flow currently covers instructions and metadata.
- Bundled script execution is not yet part of the runtime flow.
- `chatWithADK` traditional RAG routing does not use the structured skill catalog.
