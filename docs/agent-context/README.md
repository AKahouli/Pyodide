## Record rules

Keep platform and harness decisions in their separate indexes. Read applicable current ADRs before the first code edit; follow explicit superseding decisions.

- Put a platform choice in `decisions/ADR-NNNN-topic.md`; harness choices use `tools/opencode-harness/docs/decisions/HADR-NNNN-topic.md` with status, scope, source paths, decision, rationale, and verification. Supersede a decision with a new record; preserve the old one.
- Link a contract to its executable schema, proto, test, or owning source. Do not duplicate field definitions that code already owns.
- Add or update an index row when a reviewed record is added or its scope changes.
- Hindsight and agent conversations are evidence for a proposal, never authority for an accepted record. Review Git changes before treating them as approved.
