# Playbook Advisor

> **Slug:** `playbook-advisor` | **Status:** 🚧 draft | **Last Updated:** 2026-04-11 12:27:13 UTC

## Purpose
Document the shipped Playbook Advisor implementation, including the first safe `Advisor Autopilot` rollout for bounded single-step remediation.

## Scope
Includes Playbook Advisor naming, tool-aware advisor findings, defensive backend advisor normalization, persisted advisor result fields, execution-summary tool usage findings, single-step Advisor execution behavior, rerun-toggle propagation, rerun availability gating, rerun-time advisor-state resets, the Step Autopilot control loop and UI state, and newest-history selection in the advisor and evaluation panes.

## Implemented
- User-facing playbook execution copy uses `Playbook Advisor` / `Advisor` instead of `Judge LLM` / `Reflection` in the main tab, toolbar toggle, node badges/tooltips, and remediation actions.
- The backend still preserves existing `judge*` field names, routes, and prompt keys for compatibility.
- Step-level advisor results normalize and persist `confidence`, `toolUsageScore`, `toolSelectionIssues`, `missingToolCalls`, `redundantToolCalls`, `toolOutputUseIssues`, `toolSequencingIssues`, `toolUsageStrengths`, `toolUsageRecommendation`, and `safeAutoFixType`.
- Execution-level advisor summaries normalize and persist `confidence`, `toolUsageIssues`, `crossStepToolPatterns`, `rootCauseTaskIds`, and `highImpactRecommendations`.
- `PlaybookJudgeEnrichmentService` normalizes advisor payloads defensively so malformed LLM JSON degrades to bounded defaults instead of leaking invalid data into persistence or the UI.
- Single-step execution requests and step rerun requests accept Advisor Autopilot settings: `advisorAutopilotEnabled`, `advisorAutopilotTargetScore`, and `advisorAutopilotMaxTurns`.
- Step rerun requests now also accept `runNodeReflection`, so the current toolbar Advisor toggle is honored when executing a single step from an existing execution.
- Step rerun requests now fail fast with `ServiceUnavailableException` when the playbook gRPC client is unavailable, instead of reaching `RunStepStream` on an undefined client.
- Rerunning a step now clears the current step’s persisted `judgeStatus`, `judgeResult`, and `judgeError` before the next attempt starts, so synchronous advisor evaluation does not exit early on stale `evaluated` state from the previous attempt.
- The execution rerun path also refreshes `reflectionEnabled` from the current request, keeping reused executions aligned with the toolbar Advisor switch.
- The execution model stores execution-level autopilot metadata: enabled flag, target score, max turns, current status, active task id, turn count, and last error.
- Task results store append-only autopilot metadata: turn count, turn history, last advisor action, last score delta, and stop reason.
- Non-autopilot single-step runs execute the selected step and then run Playbook Advisor synchronously before the execution is finalized, so the Advisor tab is populated immediately after the step completes.
- Advisor history entries persist the originating `attemptNumber`, which lets the UI label each advisor result by the step attempt that produced it.
- The Playbook Advisor tab exposes an advisor-evaluation selector, reusing persisted advisor history so users can inspect prior advisor outputs for the same step.
- The latest persisted advisor and evaluation history entry is selected by default when a step detail panel refreshes, so fresh results are shown immediately after completion.
- The single-step Advisor Autopilot path still runs the selected step, evaluates Advisor synchronously, stops when bounded conditions are met, and otherwise applies the safe `optimize_step` rewrite before rerunning the same step in the same execution.
- A dedicated SSE event, `playbook_advisor_autopilot_updated`, keeps the active execution cache in sync with autopilot state transitions and turn history entries.

## Safety Boundaries
- Shipped scope is **single-step safe autopilot only**.
- The only auto-applied remediation is the existing safe `optimize_step` rewrite.
- Mid-run graph rewrites, task-id changes, edge rewrites, and automatic new-playbook generation are still out of scope.
- Full workflow same-thread autopilot is not implemented because the current ADK/LangGraph resume contract does not accept live graph/task rewrites.

## Validation
- Backend: `npm test -- --runInBand src/modules/playbook/services/playbook-execution.service.spec.ts`
- Backend build: `npm run build`

## Known Gaps
- Full workflow autopilot still requires deeper ADK/LangGraph contract changes or a new restart-based orchestration strategy.
- Existing historical executions still only gain attempt-numbered advisor history when they are judged again after this change.
