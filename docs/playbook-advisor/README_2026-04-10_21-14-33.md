# Playbook Advisor

> **Slug:** `playbook-advisor` | **Status:** 🚧 draft | **Last Updated:** 2026-04-10 21:14:33 UTC

## Purpose
Document the shipped Playbook Advisor implementation, including the first safe `Advisor Autopilot` rollout for bounded single-step remediation.

## Scope
Includes Playbook Advisor naming, tool-aware advisor findings, defensive backend advisor normalization, persisted advisor result fields, execution-summary tool usage findings, and the new single-step Advisor Autopilot control loop and UI state.

## Implemented
- User-facing playbook execution copy uses `Playbook Advisor` / `Advisor` instead of `Judge LLM` / `Reflection` in the main tab, toolbar toggle, node badges/tooltips, and remediation actions.
- The backend still preserves existing `judge*` field names, routes, and prompt keys for compatibility.
- Step-level advisor results normalize and persist `confidence`, `toolUsageScore`, `toolSelectionIssues`, `missingToolCalls`, `redundantToolCalls`, `toolOutputUseIssues`, `toolSequencingIssues`, `toolUsageStrengths`, `toolUsageRecommendation`, and `safeAutoFixType`.
- Execution-level advisor summaries normalize and persist `confidence`, `toolUsageIssues`, `crossStepToolPatterns`, `rootCauseTaskIds`, and `highImpactRecommendations`.
- `PlaybookJudgeEnrichmentService` normalizes advisor payloads defensively so malformed LLM JSON degrades to bounded defaults instead of leaking invalid data into persistence or the UI.
- Single-step execution requests and step rerun requests now accept Advisor Autopilot settings: `advisorAutopilotEnabled`, `advisorAutopilotTargetScore`, and `advisorAutopilotMaxTurns`.
- The execution model now stores execution-level autopilot metadata: enabled flag, target score, max turns, current status, active task id, turn count, and last error.
- Task results now store append-only autopilot metadata: turn count, turn history, last advisor action, last score delta, and stop reason.
- The single-step execution path in `PlaybookExecutionService` now supports a bounded synchronous advisor loop:
  - run the selected step
  - run Playbook Advisor synchronously
  - stop if the target score is reached, the advisor abstains, no safe fix is available, or the max-turn bound is reached
  - otherwise apply the existing safe `optimize_step` rewrite and rerun the same step in the same execution
- The frontend now exposes a `Step Autopilot` toggle in the playbook toolbar, sends the autopilot settings on single-step runs/reruns, and shows live autopilot status plus stop reason in the Playbook Advisor panel.
- A dedicated SSE event, `playbook_advisor_autopilot_updated`, now keeps the active execution cache in sync with autopilot state transitions and turn history entries.

## Safety Boundaries
- Shipped scope is **single-step safe autopilot only**.
- The only auto-applied remediation is the existing safe `optimize_step` rewrite.
- Mid-run graph rewrites, task-id changes, edge rewrites, and automatic new-playbook generation are still out of scope.
- Full workflow same-thread autopilot is not implemented because the current ADK/LangGraph resume contract does not accept live graph/task rewrites.

## Validation
- Backend: `npm test -- modules/playbook/services/playbook-judge-enrichment.service.spec.ts --runInBand`
- Frontend: `npm test -- src/modules/playbook/components/ExecutionStepDetail.test.tsx src/modules/playbook/components/PlaybookToolbar.test.tsx`
- Backend build: `npm run build`
- Frontend build: `npm run build`

## Known Gaps
- Full workflow autopilot still requires deeper ADK/LangGraph contract changes or a new restart-based orchestration strategy.
- The toolbar autopilot toggle currently targets step execution/rerun flows; full playbook runs keep the existing non-blocking advisor behavior.
- Existing historical executions will not have autopilot metadata until they are run again.
