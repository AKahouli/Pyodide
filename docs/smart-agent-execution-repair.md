# Smart Agent execution repair — 2026-10-10

## Implementation and boundaries

The conversation agent chooses execution using its existing `mono-agent-work-orchestration` skill (version 1.2.0). The runtime now reinforces the distinction between the conversational root and execution-only leaves.

- **Connector preservation:** `YellowStorm/back/src/modules/agent/agent.service.ts` supplies the authorized connector bindings in both the typed stream definition and its native JSON representation. Previously the root could use web search while its frozen temporary-worker ceiling contained no connectors. New executions retain authorized connector actions; old frozen ceilings are not widened.
- **Leaf execution:** `yellowstorm-adk/src/root_runtime/compiler.py` excludes root orchestration/navigation skills and native conversational choices from leaf workers. `worker_execution.py` reports bounded tool names and stops after six consecutive nonproductive tool responses or forty scoped model turns. It reconstructs the budget from history so resumption does not reset it.
- **Deliverable settlement:** `worker_result.py`, `dispatcher.py`, `background_host.py`, and backend `root-delegate-definition.service.ts` reject empty completed results without an available artifact locator. Nested artifact payloads have consistent validation. Rejection is a failure, not an empty successful result.
- **Provider recovery:** `model_response_recovery.py` permits one recovery attempt for a wholly empty provider response only before tool history exists. It never restarts a workflow, retries an error/cancellation/token limit, or repeats actions. Usage from both attempts is retained. `instrumented_lite_llm.py` omits `parallel_tool_calls` on tool-less requests without mutating a model shared by concurrent requests.
- **Publication:** `root-followup-writer.ts` defers foreground admission conflicts within a savepoint, including the current session uniqueness trigger. Frozen original-request context reaches synthesis so requested tables and direct links survive. Counts exclude coordinator/followup records. Model metadata uses actual synthesis usage, with the frozen request model as fallback.
- **Source interaction:** `root-followup-evidence.ts` retains validated public web URLs, titles, producer identities, and global citation aliases. Queries, fragments, credentials, and unsafe protocols cannot become clickable source links. The frontend still authorizes owned evidence before opening its registered URL; document evidence keeps its scoped preview path.
- **Chat state:** Pending tool payloads display a waiting state during streaming and load after persistence. Failed fanout leaves and partial cancellations remain visible after final-answer preparation.
- **Clarification continuity:** Validated `adk_request_input` submissions are retained with immutable invocation/input/version identities before the frozen continuation resumes. Stale state writes preserve these accepted answers. The sealed synthesis packet includes their exact constraints; they are user submissions, not proof that an external action ran.
- **Fresh publication metadata:** The shared work observer refreshes each final publication once even when an earlier copy of that message is already cached, allowing the owned source handler to receive the final authorized URL/type/title without a page reload.
- **Uncertain fanout:** Owned settlement and authoritative expiry reconcile only existing, nonterminal children from the validated frozen manifest to `outcome_unknown`. Completed siblings, evidence, receipts and absent reserved IDs remain unchanged. This avoids falsely showing abandoned workers as Running; it does not confirm external effects or retry an uncertain action.

- **Paged evidence:** A live trip worker performed 24 successful searches but lost its completed result because aggregate evidence exceeded the 100-entry settlement DTO limit. Ordinary delegates, standalone background workers and fanout leaves now stage immutable evidence in pages (at most 100 entries and 64 KiB native wire data), then settle once with an exact identity count/digest. The backend verifies the staged set and result references atomically under existing actor/root/epoch and ownership fences. Staged records remain private until completed-result authorization permits them. The execution envelope is bounded to 1,000 records and 1 MiB server data (768 KiB native wire data); exceeding it fails explicitly rather than dropping sources or repeating tools. The initial synthesis preview remains 100 aliases, with an explicit truncation flag requiring complete producer alias retrieval through the existing synthesis-result page.
- **Authoritative source routing:** The authorized evidence response provides an optional web classification for registered web citations without private-document bindings. Source clicks use it even if the first cached message still presents the source as a document.

New registered events are `worker.profile.resolved`, `worker.execution.rejected`, `worker.evidence.staged`, and `job.execution.outcome_unknown`. Action-ledger failures use the existing `tool.call.failed` event with a bounded phase (`invoke`, `authorize_receipt`, `serialize_receipt`, `commit_receipt`) and the detailed originating exception. The supervisor emits concise correlated uncertainty; no prompt/result content is logged. Shared SDK contracts and staged consumer lock integrities were synchronized.
