# Playbook Architecture

> **Slug:** `playbook` | **Status:** 🚧 draft | **Last Updated:** 2026-04-07 22:02:15

## Purpose
Document the playbook execution system and the integration points an AI coding agent needs to extend it safely.

## Scope
Includes frontend streaming behavior, backend workflow execution, gRPC stream consumption, cancellation handling, replay, evaluation, undo/redo, HITL copilot, prompt registry behavior, copilot response input handling, backend crash diagnostics, stream error-containment behavior, and ambiguous artifact routing resolution.
Excludes unrelated modules outside the playbook domain.

## Architecture
Playbook workflow execution runs through gRPC streaming calls from Nest to the ADK service. The backend buffers step updates, forwards them to the frontend over SSE, and finalizes the execution when the gRPC stream terminates.

Prompt templates are managed through the playbook prompt registry. The backend resolves the latest enabled templates, serializes them into `prompt_overrides`, and passes them through gRPC so the ADK can apply them when building task prompts, structured-output routing prompts, replay prompts, and the playbook generation preprompt.

Clarification context is persisted in playbook execution state: `clarification_transcripts_by_task` stores the turn-by-turn HITL transcript and `task_description_overrides_by_task` stores the clarified task text. Clarification interrupt payloads include `task_description`, so the backend can persist the clarified description alongside `conversation_json`, `interrupt_id`, `round`, and `resumable_actions`.

On resume, the ADK reconstructs the suspended interrupt snapshot before resuming execution. `resume_playbook()` and `resume_single_step()` both build a state update from the stored interrupt snapshot, then resume with `Command(update=..., resume=...)` so the prior transcript and task-description context are restored before the graph continues.

The task completion path computes `output_text` before fallback artifact generation in `graph_builder`. That order prevents the `cannot access local variable 'output_text'` failure when a step completes with only fallback text artifacts.

Copilot response entry points use multiline textareas in both `PlaybookDesignerPanel` and `InterruptDialog`. Their keydown handlers submit on plain Enter, call `preventDefault()` before submit, keep Shift+Enter available for newline insertion, and skip submission while IME composition is active.

Backend bootstrap serializes `unhandledRejection` reasons with `node:util.inspect`. `Error` rejections log type, message, stack, name, and cause, while non-Error rejections log inspected object output.

The stream data handlers guard `handleStepUpdate()` in both full-workflow and single-step streaming modes. If artifact extraction or another step-update operation throws while processing a gRPC `data` chunk, the backend logs the exception, cancels the stream, and rejects the execution promise.

Artifact output-port resolution in both the ADK and Nest backend now falls back gracefully when routing is ambiguous. When a task produces an artifact without `output_port_id` and multiple compatible output ports exist, the resolver prefers the `default` port (if one exists among the candidates) or otherwise returns the first compatible port with a warning log. This replaces the previous hard error that would crash the backend or fail the step.

The ADK deterministic heuristic now includes fuzzy matching via `difflib.SequenceMatcher`. When exact filename token matching fails, the resolver scores the artifact filename stem against each candidate port's `id`, `name`, and `description` fields, ranking by best similarity score with a 0.5 threshold. When multiple candidates remain after filename inference in `_resolve_output_port`, they are ranked by similarity to the component label or filename. The LLM routing call in `step_executor` is kept as a final safety net but is no longer the primary disambiguation path.

The structured-output synthesis path in the ADK step executor also falls back when the LLM routing call returns empty for semantically ambiguous ports, instead of hard-failing the step. It logs a warning and continues with component-level artifact extraction.

The stream finalization path distinguishes between:

- genuine premature stream termination while work is still pending
- locally cancelled streams that end without emitting a gRPC `error` event

## Requirements
- As a user, I want workflow execution to stay responsive while live progress streams.
- As a user, I want a manually stopped workflow to finish as `cancelled`, not `failed`.
- As a backend consumer, I want locally cancelled gRPC streams to finalize correctly even when the client library emits `end` instead of `error`.
- As a user, I want resumed HITL clarification runs to restore the stored clarification transcript and task description context from the suspended interrupt snapshot so the same clarification is not asked twice.
- As a user, I want fallback-only step completions to succeed without a runtime error so text artifacts can still be generated.
- As an admin, I want to edit playbook prompts, including the generation preprompt, so new playbook drafts can use updated instructions without redeploying.
- As a user, I want copilot replies in the designer panel and interrupt dialog to submit on plain Enter while Shift+Enter inserts a newline, so multiline feedback stays fast to enter.
- As a backend operator, I want unhandled promise rejections to include real error details so workflow crashes can be diagnosed from logs instead of opaque `{}` payloads.
- As a backend operator, I want streamed step-update exceptions to fail the active execution without killing the whole API process.
- As a user, I want artifact routing to succeed even when the ADK does not set `output_port_id`, as long as the task has at least one compatible output port, so workflows with multiple output ports do not crash.

## API / Interfaces
- `PlaybookExecutionService.consumePlaybookStream()` consumes the full-workflow gRPC stream and decides whether to complete, interrupt, cancel, or fail the execution.
- `PlaybookExecutionService.executeStepWithStreaming()` consumes the single-step `RunStepStream` gRPC stream and resolves the step outcome for manual/single-step execution.
- `PlaybookExecutionService.handleStepUpdate()` normalizes streamed step results, extracts artifacts/components/output, and updates the in-memory step buffer before SSE fanout.
- `PlaybookGrpcService.markCancelled(executionId)` marks an execution as locally cancelled before the Nest client calls `cancel()` on the active stream.
- `PlaybookGrpcService.wasCancelled(executionId)` is consulted from both the stream `error` path and the stream `end` path.
- `markExecutionCancelled()` emits `playbook_execution_complete` with `status: cancelled` and skips still-running/pending tasks.
- `resolveOutputPort()` in `execution.utils.ts` returns the `default` port or the first compatible port when routing is ambiguous, instead of throwing.
- `_resolve_output_port()` in `graph_builder.py` mirrors the same fallback behavior on the ADK side.
- `YellowStorm/back/src/main.ts` serializes `unhandledRejection` reasons before shutdown, using `inspect()` for the rejected promise reason and special handling for `Error` instances.

## Design Decisions
| Decision | Rationale | Alternatives Considered |
|----------|-----------|------------------------|
| Check the local cancellation flag inside the stream `end` handler | Some gRPC client cancellations complete via `end` without surfacing an `error`, so the backend must not treat that path as an unexpected workflow failure | Only handling cancellation in the `error` handler |
| Keep premature-end failure logic for non-cancelled streams | Unexpected stream termination with pending/running tasks is still a real execution failure signal that the UI should surface | Treating every ended stream as cancelled or successful |
| Route playbook prompts through `prompt_overrides` | Keeps prompt edits in the same registry and lets the ADK reuse one payload for task prompts, replay prompts, routing prompts, and generation preprompts | Separate config source for generation prompts |
| Persist clarification transcripts and task description overrides in execution state | Resumed HITL runs need the original clarification context to replay cleanly instead of asking the same question again | Rebuilding clarification context only from the in-memory interrupt payload |
| Include `task_description` in clarification interrupt payloads and restore from the suspended snapshot before resuming | The clarified task text must survive suspension so the resumed graph continues with the same task context | Recomputing the description from the original task definition during resume |
| Compute `output_text` before fallback artifact generation in the task completion path | Fallback-only completions still need the completed output captured before artifact generation can run | Deriving `output_text` from the fallback artifact after generation |
| Handle Enter submission in the textarea keydown handler | The response areas stay multiline while still supporting keyboard-first submission, and Shift+Enter remains available for explicit newlines | Converting the inputs to single-line fields or requiring click-only submission |
| Serialize unhandled rejection reasons before shutdown | Backend crash logs must preserve enough detail to debug workflow failures, especially when some rejected values are plain objects instead of `Error` instances | Logging the raw `reason` object and relying on the logger serializer |
| Catch `handleStepUpdate()` exceptions inside gRPC `data` handlers | Artifact extraction and stream normalization errors should fail the current execution, not bubble out of the event emitter and crash the API process | Letting event-callback exceptions propagate to the global `unhandledRejection` handler |
| Fall back to `default` port when artifact routing is ambiguous | When the ADK does not emit `output_port_id` and multiple ports share an artifact kind, preferring `default` is a safe semantic default that most playbook authors expect | Hard-failing the execution or requiring the ADK to always produce explicit port assignments |
| Fall back to first compatible port when no `default` port exists | Some tasks deliberately use named ports without a `default` port; returning the first match is still better than crashing | Returning `null` and silently dropping the artifact |
