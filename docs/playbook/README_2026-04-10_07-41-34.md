# Playbook Architecture

> **Slug:** `playbook` | **Status:** 🚧 draft | **Last Updated:** 2026-04-10 07:41:34 UTC

## Purpose
Document the playbook execution system and the integration points an AI coding agent needs to extend it safely.

## Scope
Includes frontend streaming behavior, backend workflow execution, gRPC stream consumption, cancellation handling, replay, evaluation, undo/redo, HITL copilot, prompt registry behavior, copilot response input handling, backend crash diagnostics, stream error-containment behavior, ambiguous artifact routing resolution, and post-execution judge/reflection flows.

## Implementation Notes
- Playbook execution requests now accept `runNodeReflection`.
- Execution state stores reflection and judge summary metadata alongside task-level judge status, result, error, and history.
- `PlaybookJudgeEnrichmentService` schedules node reflection asynchronously after step completion, re-sweeps completed executions, enqueues pending node judges so the limiter can process them in parallel, and uses longer per-call LiteLLM timeouts for node judge, execution summary, and rewrite requests.
- In the workflow stream path, completed steps are now flushed to persistence before semantic evaluation and node reflection are scheduled, so node judge work can start immediately after each node completes.
- The frontend merge logic preserves richer cached judge state over stale fetched task rows with the same step status, so `evaluating` and `evaluated` badges are not reset back to `idle` during active runs.
- The frontend still polls completed executions briefly so judge results appear if the SSE stream closes before the reflection finishes.
- Judge prompts are registered through `PlaybookPromptService` for node reflection, execution summary, and the two rewrite actions.
- The playbook controller exposes reflection actions to update the current playbook or generate a new optimized playbook from an execution.

## UI Notes
- Canvas nodes show judge state and score badges.
- The toolbar exposes a reflection toggle for execution runs.
- The execution detail view exposes a Judge LLM tab that shows node-level judge output, node-level judge failures, and a single execution-level recommendation/CTA block.
